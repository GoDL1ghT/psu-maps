# psu-maps

Мобильное приложение на Expo + React Native: карта, на которую пользователь ставит метки долгим
нажатием, и галерея фотографий для каждой метки. Данные хранятся в локальной базе SQLite,
а приложение следит за геопозицией и предупреждает, когда вы подходите к сохранённой метке.

## Установка и запуск

```bash
npm install
npx expo start
```

Дальше отсканируйте QR-код приложением **Expo Go** (Android/iOS). Нативные SDK и ключи Google Maps
не нужны: `react-native-maps` входит в Expo Go для SDK 57.

### Ограничения Expo Go на Android

Две вещи в Expo Go не работают — обе из-за самого Expo Go, а не из-за кода приложения:

| Что | Почему | Что делает приложение |
| --- | --- | --- |
| Базовая карта Google пустая (виден только логотип) | Expo Go не может получить свой ключ Maps SDK: `Error requesting API token. StatusCode=INVALID_ARGUMENT` ([issue](https://github.com/react-native-maps/react-native-maps/issues/5888)) | подставляет тайлы OpenStreetMap через `UrlTile`, так что карта видна |
| Не приходят уведомления | push-функциональность вырезана из Expo Go с SDK 53, и `expo-notifications` падает при импорте | грузит модуль лениво и показывает предупреждение в панели |

Обе проблемы исчезают в development build, где используются штатные тайлы Google и настоящие
уведомления:

```bash
npx expo run:android                                  # локально (нужен Android SDK)
npx eas build --profile development --platform android  # или через EAS
```

Проверка типов и сборка бандла:

```bash
npx tsc --noEmit
npx expo export --platform android
```

Логи операций с базой выводятся в консоль Metro в режиме разработки (префикс `[db]`).

## Возможности

- Полноэкранная карта (`react-native-maps`), стартовый регион — кампус ПГНИУ.
- Долгое нажатие по карте создаёт метку; пины кликабельны и ведут на экран деталей.
- Панель со списком меток: координаты, количество фото, удаление с подтверждением.
- Экран метки: координаты, дата, сетка фотографий, добавление из галереи, удаление фото.
- Просмотр фото на весь экран по нажатию.
- Всё хранится в SQLite и переживает перезапуск приложения.
- Текущее местоположение на карте и расстояние до каждой метки в списке.
- Локальное уведомление при входе в радиус 100 м от метки — по одному на метку.
- Тёмная и светлая темы.

## База данных

```sql
CREATE TABLE markers (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    latitude REAL NOT NULL,
    longitude REAL NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE marker_images (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    marker_id INTEGER NOT NULL,
    uri TEXT NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (marker_id) REFERENCES markers (id) ON DELETE CASCADE
);

CREATE INDEX idx_marker_images_marker_id ON marker_images (marker_id);
```

- Связь «одна метка — много изображений»; удаление метки каскадом уносит её фотографии.
  `PRAGMA foreign_keys = ON` включается при открытии соединения, иначе SQLite игнорирует внешние
  ключи.
- Версия схемы хранится в `PRAGMA user_version`. `migrateDatabase` прогоняет миграции по порядку
  от текущей версии до `DATABASE_VERSION`, так что новая версия добавляется одной функцией в
  массив `migrations`.
- `PRAGMA journal_mode = WAL` — быстрее при частых записях.
- Индекс по `marker_id` ускоряет выборку фотографий метки.
- Список меток приходит одним запросом с `LEFT JOIN` и `COUNT`, поэтому счётчик фото не требует
  отдельных обращений к базе.
- ORM не используется: запросов немного, а прямой SQL на `expo-sqlite` не добавляет в сборку
  лишний слой и полностью типизирован через дженерики `getAllAsync<T>()`.

## Решения при реализации

- **Слой данных отделён от UI.** `src/database/operations.ts` — чистые функции над
  `SQLiteDatabase`, `DatabaseProvider` — соединение, кэш списка меток и статусы, экраны —
  только отображение. Компоненты не знают SQL.
- **Транзакции.** Удаление метки и вставка нескольких фотографий идут через
  `withExclusiveTransactionAsync`, чтобы частично применённых изменений не оставалось.
- **Освобождение ресурсов.** Соединение закрывается в функции очистки `useEffect`; ответы
  асинхронных операций игнорируются, если провайдер уже размонтирован.
- **Числовые id.** Идентификаторы меток и изображений — числа, как в схеме БД.
- **Типизация.** Все данные описаны в `src/types.ts`; параметры маршрута читаются через
  `useLocalSearchParams<MarkerDetailsParams>()`, переходы — через типизированные маршруты
  (`experiments.typedRoutes`).
- **Разрешения.** Доступ к галерее запрашивается перед открытием пикера; если пользователь
  отказал навсегда, приложение предлагает открыть системные настройки.

## Геолокация и уведомления

- `useLocationTracking` запрашивает разрешение, читает последнюю известную позицию (чтобы карта не
  ждала фикс GPS) и подписывается на `watchPositionAsync` с `Accuracy.Balanced`, интервалом 5 с и
  порогом 5 м. Подписка живёт только пока приложение активно: смена `AppState` снимает её и
  поднимает заново, так что фоновых обновлений и лишнего расхода батареи нет.
- Расстояние считается формулой гаверсинуса (`calculateDistance`, метры) — без сторонних библиотек.
- Вокруг каждой метки на карте рисуется круг радиусом 100 м; метка, в зоне которой вы находитесь,
  подсвечивается, и в списке у неё появляется пометка «рядом».

### Стратегия уведомлений

- **Expo Go на Android уведомления не поддерживает.** Модуль `expo-notifications` бросает
  исключение прямо при импорте: `DevicePushTokenAutoRegistration.fx` регистрирует слушателя
  push-токена на уровне модуля, а эта функциональность вырезана из Expo Go с SDK 53. Поэтому
  модуль подгружается лениво (`loadNotifications()`) и только там, где он работает: в Expo Go на
  Android приложение показывает предупреждение в панели и продолжает работать без уведомлений —
  карта, метки, база и трекинг геопозиции не затронуты. Чтобы получить уведомления, нужен
  development build: `npx expo run:android` или сборка через EAS.
- `NotificationManager` держит `Map<markerId, ActiveNotification>` в памяти: пока уведомление по
  метке активно, повторное не отправляется.
- Вход в зону — расстояние ≤ 100 м, выход — > 140 м. Разные пороги (гистерезис) не дают
  уведомлению мигать, когда точность GPS «дрожит» на границе.
- Выход из зоны снимает уведомление из шторки: `dismissNotificationAsync` для уже показанного
  плюс `cancelScheduledNotificationAsync` на случай, если оно ещё в расписании.
- Удалённые метки убираются из активных через `syncWithMarkers`, при размонтировании экрана
  вызывается `reset()`.
- Между запусками приложения состояние не сохраняется: карта активных уведомлений живёт в памяти,
  как и требует задание.

### Как проверить

1. Запустите приложение в Expo Go и разрешите доступ к геопозиции и уведомлениям.
2. Поставьте метку в 50–100 м от текущей позиции — уведомление придёт при следующем обновлении
   координат (до 5 с).
3. Подмените координаты: **Android-эмулятор** — Extended controls → Location → Set location;
   **iOS-симулятор** — Features → Location → Custom Location; на устройстве — приложение для
   подмены GPS в режиме разработчика.
4. Уйдите дальше 140 м — уведомление исчезнет из шторки; вернитесь — придёт заново.
5. Отключите службы геолокации или откажите в разрешении — в панели появится сообщение с кнопкой
   «Повторить».

## Обработка ошибок

Ошибки обрабатываются на трёх уровнях: слой БД бросает понятные `Error`, контекст различает
фатальную ошибку инициализации (`error` + кнопка «Повторить») и ошибки отдельных операций
(пробрасываются вызывающему), экраны показывают `Alert` или экран‑заглушку.

| Место | Что делает приложение |
| --- | --- |
| Инициализация БД | ошибка открытия или миграции показывает экран «База данных недоступна» с повтором подключения |
| Транзакции | `withExclusiveTransactionAsync` откатывает изменения целиком; удаление несуществующей записи бросает ошибку вместо тихого «успеха» |
| Ограничения внешнего ключа | вставка фото к удалённой метке не проходит: SQLite возвращает `FOREIGN KEY constraint failed`, текст показывается в `Alert` |
| Обращение до готовности БД | операции бросают «База данных ещё не готова» вместо падения на `null` |
| Геолокация | выключенные службы, отказ в разрешении и ошибки `watchPositionAsync` показываются строкой в панели с кнопкой «Повторить»; карта продолжает работать без геопозиции |
| Уведомления | отказ в разрешении не ломает трекинг — приложение показывает предупреждение и просто не шлёт уведомления |
| Выбор изображения | `try/catch` вокруг пикера, `Alert` с текстом ошибки, отдельная ветка для отказа в разрешении |
| Навигация | id метки валидируется; несуществующая метка показывает экран «Метка не найдена» с кнопкой возврата, `router.back()` подстрахован `router.replace('/')` |
| Загрузка карты | индикатор до `onMapReady`; если карта не поднялась за 12 секунд — экран с кнопкой «Повторить» |
| Непредвиденные ошибки | каждый маршрут экспортирует `ErrorBoundary` с кнопкой повторного рендера |

## Известные ограничения

- Веб-версия не поддерживается: `react-native-maps` работает только на Android и iOS, а
  `withExclusiveTransactionAsync` недоступен в вебе.
- Отслеживание работает только на переднем плане: фоновая геолокация требует dev-build,
  разрешения `ACCESS_BACKGROUND_LOCATION` и проверки в Google Play.
- Активные уведомления не переживают перезапуск приложения: после рестарта метка, в зоне которой
  вы стоите, уведомит заново.
- В Expo Go на Android уведомления не приходят вообще (см. раздел «Стратегия уведомлений») —
  нужен development build. Остальная функциональность в Expo Go работает полностью.
- URI фотографий ссылаются на галерею устройства; файлы в приложение не копируются.
